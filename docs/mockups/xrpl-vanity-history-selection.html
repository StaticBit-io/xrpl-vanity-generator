History — multi-select, bulk export and delete confirmation

Two changes to the History page. Every result carries a seed that exists nowhere else on disk, so deleting one is unrecoverable: destructive actions now go through a confirmation dialog instead of happening on a single click. And rows can be picked — a few, or all of them — to export or delete together, rather than one at a time.

A selection bar appears under the filter and holds the actions that operate on it, so the header buttons never change their meaning mid-click: Export TSV… greys out while a selection exists, because the selection bar is now the place to export from. The header checkbox shows a dash when only part of the visible list is picked. Picked rows are tinted, and the count is the anchor — 3 selected, not "some rows". Selection is remembered by address, so typing in the filter hides rows without unpicking them; the bar keeps saying how many are held.

The dialog is drawn inside the page, like the existing close prompt — not a system message box — so it keeps the palette and cannot appear behind the window. The list beneath stays visible through the backdrop, which is what makes "3 selected" checkable at a glance before confirming.

05 Read-only store

When results.dat cannot be written, the red banner already replaces the storage footer and the destructive buttons disappear. That stays: the checkbox column and Export selected… remain — reading and exporting are still safe — while Delete selected and Clear history are gone rather than disabled, since nothing the user could do would make them work.
