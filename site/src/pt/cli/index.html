Linha de comando xrpl-vanity

A mesma busca de endereços personalizados do aplicativo, a partir de um terminal no Windows ou no Linux.

Compile

Não há binários prontos: rode a partir do código com o .NET 10 SDK.

$ git clone https://github.com/StaticBit-io/xrpl-vanity-generator.git
$ cd xrpl-vanity-generator
$ dotnet run --project src/XrplVanity.Cli -c Release -- --contains xrp --count 1

A primeira execução compila o programa. Nos exemplos abaixo, xrpl-vanity significa dotnet run --project src/XrplVanity.Cli -c Release --.

Onde a palavra fica

Uma palavra sem opção precisa aparecer no início do endereço, logo depois do r inicial. Uma execução pode misturar posições, e um endereço vale se qualquer padrão coincidir.

$ xrpl-vanity ripple hodl xrp
$ xrpl-vanity --ends xyz --contains dao
$ xrpl-vanity --starts-ends abc:xyz
$ xrpl-vanity --list words.txt 5

--starts-ends exige as duas metades no mesmo endereço, então custa o mesmo que uma palavra com o tamanho das duas somadas. A última linha carrega as palavras de um arquivo e fica com as de pelo menos 5 caracteres.

Opções

OpçãoPadrãoO que faz
--starts PnenhumCoincide no início do endereço, depois do r. Pode repetir. Palavras sem opção fazem o mesmo.
--near-start PnenhumA palavra pode começar no 2º ou 3º caractere. Pode repetir.
--ends PnenhumCoincide no fim do endereço. Pode repetir.
--contains PnenhumCoincide em qualquer lugar. Pode repetir.
--starts-ends PREFIX:SUFFIXnenhumExige um início e um fim no mesmo endereço. Pode repetir.
--near-starts-ends PREFIX:SUFFIXnenhumO mesmo, com o início permitido no 2º ou 3º caractere. Pode repetir.
--list FILE [minLen]minLen 4Carrega de um arquivo palavras para o início do endereço.
--case-sensitivedesligadoBusca exatamente como digitado. Por padrão, qualquer combinação de maiúsculas e minúsculas vale para palavras de até 12 caracteres.
--threads Ntodos os núcleosLinhas de execução para buscar no processador. Ignorado com --gpu.
--out FILEnenhumAcrescenta os resultados a um arquivo, além de mostrá-los.

--gpudesligadoBusca na placa de vídeo: primeiro CUDA, depois OpenCL.
--backend NAMEnenhumForça cuda ou opencl. Implica --gpu.
--device NnenhumEscolhe um dispositivo pelo índice. Implica --gpu.
--list-devicesnenhumLista todos os dispositivos e sai.
--gpu-devices SPECnenhumUsa vários dispositivos ao mesmo tempo: all, cuda, opencl ou uma lista separada por vírgulas. Implica --gpu.
--gpu-duty N100Mantém a placa de vídeo ocupada cerca de N% do tempo, de 1 a 100.

Quais palavras funcionam

Os endereços usam 58 caracteres. 0, O, I e l não existem, então sua palavra é ajustada: l vira L, 0 e O viram o, e I vira i. Se uma palavra ainda tiver um caractere impossível, o programa avisa e a ignora.

Cada caractere a mais multiplica a espera: por até 58 com --case-sensitive e por menos sem ele, porque mais grafias contam como resultado.

O primeiro caractere depois do r costuma ser um de pshnaf39wBUDNEGHJKLM4PQ. Uma palavra que começa com outro é cerca de 23 vezes mais rara do que o tamanho sugere. --near-start a deixa começar um caractere depois, o que a encontra cerca de 24 vezes mais rápido.

Buscar na placa de vídeo

$ xrpl-vanity --list-devices
$ xrpl-vanity --gpu --contains dao --count 1
$ xrpl-vanity --gpu-devices cuda --starts abc
$ xrpl-vanity --gpu --gpu-duty 80 --contains dao --count 1 --out dao.tsv

Cada resultado da placa de vídeo é derivado de novo no processador e só é mostrado se os dois baterem: um dispositivo com defeito custa velocidade, mas nunca entrega uma chave errada. Sem um dispositivo utilizável, --gpu sai com código 2 em vez de passar para o processador.

A primeira execução com OpenCL pode levar dezenas de segundos enquanto o driver compila o programa. As seguintes são rápidas. --gpu-duty deixa espaço para outros aplicativos, e a velocidade cai mais ou menos na mesma proporção. --gpu-devices all abre cada placa uma vez por backend, então use --gpu-devices cuda para usar cada placa NVIDIA uma única vez.

Resultados e códigos de saída

Cada resultado é uma linha no terminal:

Address: r...	Seed: sEd...

--out FILE acrescenta o mesmo par, separado por tabulação e sem os rótulos. Avisos e a velocidade final vão para o stderr, então redirecionando o stdout você fica só com os resultados.

Quem tem a seed controla a conta. Os resultados ficam em texto puro, no terminal e nesse arquivo, e em nenhum outro lugar. Mantenha-os em sigilo.

CódigoSignificado
0A meta de --count foi atingida.
2Uso inválido, nenhum padrão possível, nenhuma placa de vídeo utilizável ou uma busca que falhou.
130Encerrado com Ctrl+C antes de atingir a meta de --count.
