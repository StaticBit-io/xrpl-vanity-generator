Kommandozeile xrpl-vanity

Dieselbe Suche nach Vanity-Adressen wie in der Desktop-Anwendung, aus einem Terminal unter Windows oder Linux.

Bauen

Fertige Programmdateien gibt es nicht: Starten Sie es aus dem Quellcode mit dem .NET 10 SDK.

$ git clone https://github.com/StaticBit-io/xrpl-vanity-generator.git
$ cd xrpl-vanity-generator
$ dotnet run --project src/XrplVanity.Cli -c Release -- --contains xrp --count 1

Der erste Aufruf baut das Programm. In den Beispielen unten steht xrpl-vanity für dotnet run --project src/XrplVanity.Cli -c Release --.

Wo das Wort stehen soll

Ein Wort ohne Option muss am Anfang der Adresse stehen, direkt nach dem führenden r. Ein Aufruf kann Positionen mischen, und eine Adresse passt, wenn irgendein Muster passt.

$ xrpl-vanity ripple hodl xrp
$ xrpl-vanity --ends xyz --contains dao
$ xrpl-vanity --starts-ends abc:xyz
$ xrpl-vanity --list words.txt 5

--starts-ends verlangt beide Hälften in derselben Adresse und dauert daher so lange wie ein Wort ihrer gemeinsamen Länge. Die letzte Zeile lädt ihre Wörter aus einer Datei und behält die mit mindestens 5 Zeichen.

Welche Wörter gehen

Adressen nutzen 58 Zeichen. 0, O, I und l gibt es nicht, daher wird Ihr Wort angepasst: l wird zu L, 0 und O werden zu o, und I wird zu i. Enthält ein Wort danach noch ein unmögliches Zeichen, wird es gemeldet und übersprungen.

Jedes weitere Zeichen verlängert die Wartezeit: um bis zum 58-Fachen mit --case-sensitive und um weniger ohne, weil dann mehr Schreibweisen als Treffer zählen.

Das erste Zeichen nach dem r ist meist eines von pshnaf39wBUDNEGHJKLM4PQ. Ein Wort, das mit etwas anderem beginnt, ist etwa 23-mal seltener, als seine Länge vermuten lässt. --near-start lässt es ein Zeichen später beginnen und findet es so etwa 24-mal schneller.

Suche auf der Grafikkarte

$ xrpl-vanity --list-devices
$ xrpl-vanity --gpu --contains dao --count 1
$ xrpl-vanity --gpu-devices cuda --starts abc
$ xrpl-vanity --gpu --gpu-duty 80 --contains dao --count 1 --out dao.tsv

Jeder Treffer der Grafikkarte wird auf dem Prozessor neu abgeleitet und nur ausgegeben, wenn beide übereinstimmen: Ein fehlerhaftes Gerät kostet Geschwindigkeit, liefert aber nie einen falschen Schlüssel. Ohne nutzbares Gerät beendet sich --gpu mit Code 2, statt auf den Prozessor auszuweichen.

Der erste OpenCL-Lauf kann einige Dutzend Sekunden dauern, während der Treiber das Programm kompiliert. Spätere Läufe sind schnell. --gpu-duty lässt anderen Programmen Platz, und die Geschwindigkeit sinkt etwa im gleichen Maß. --gpu-devices all öffnet jede Karte einmal pro Backend, nutzen Sie also --gpu-devices cuda, um jede NVIDIA-Karte genau einmal einzusetzen.

Ergebnisse und Exit-Codes

Jeder Treffer ist eine Zeile im Terminal:

Address: r...	Seed: sEd...

--out FILE hängt dasselbe Paar an, durch einen Tabulator getrennt und ohne Beschriftung. Warnungen und die Endgeschwindigkeit gehen nach stderr, über stdout kommen also nur Treffer.

Wer den Seed besitzt, verfügt über das Konto. Treffer stehen im Klartext im Terminal und in dieser Datei, sonst nirgends. Halten Sie sie privat.

CodeBedeutung
0Das Ziel von --count ist erreicht.
2Falscher Aufruf, kein erreichbares Muster, keine nutzbare Grafikkarte oder eine fehlgeschlagene Suche.
130Mit Ctrl+C beendet, bevor das Ziel von --count erreicht war.
